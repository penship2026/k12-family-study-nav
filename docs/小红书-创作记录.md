## 二、正文（可直接复制，约 900 字）

给自己孩子做学习规划，最难受的不是没资源，是资源太多：书单、微课、分级读物、竞赛、教材版本、每周打卡表，散在十几个地方，每次都要重新找一遍。

所以我干脆做了一个站，把这堆东西收进 8 个页面。

不是内容站，是索引站。不上传课件、不托管视频、不放教材正文，只做"该做什么 + 去哪儿做"。

七个栏目，各解决一个问题：

· 学习规划：一～六年级 × 课内 10 门 + 课外 8 模块，共 18 项，每项写清目标、每天多久、具体任务，勾选存在本地
· 能力要求：1–12 年级的课标要求，课时比例、识字量、古诗文篇数、高中数学学分制，全部翻译成家庭动作
· 课程推荐：每科"1 条主线 + 少量加餐"，标注渠道和年级，不堆清单
· 资料清单：教育部阅读指导目录小学段 110 种全表，按学段折叠、按四类筛选
· 赛事白名单：2025—2028 学年 47 项全国性竞赛全表，按类别和学段双重筛选
· 每周打卡：11 行的 A4 横向表格，一页打印
· 教材目录：小学到高中 1911 册官方电子教材的册次索引

所有内容都锚在官方文件上：义务教育课程方案和课程标准（2022 年版）、普通高中课程方案（2017 年版 2020 年修订）、教育部阅读指导目录（2020 年版）、教监管厅函〔2025〕7 号的竞赛名单。

三个刻意的决定：

1. 纯静态。没有后端、没有数据库、没有登录，双击就能打开，扔进网盘也能打开。任务进度存 localStorage，换设备会重置——这个代价我认，因为"能用"比"同步"重要。
2. 只挂主域名，不挂深链。具体课程页三个月就可能失效，主域名能活五年。
3. 不做评分和排名。打卡只勾选，不算分，不给"完成度 87%"这种压力。

最花时间的是教材目录，因为它撞上了版权。

教案是职务作品，学校两年内有优先使用权；教材是法人作品＋汇编作品，出版还要资质；公网传播不属于合理使用。疫情期间有人把电子课本传上网，北京互联网法院判了 15 起。

所以这一页彻底放弃了内容承载：只展示单元名、章节标题、起点页码、知识点条目，每一条都挂官方电子教材链接，正文插图习题一个字不放。

数据从平台公开清单来，3565 条原始记录，剔掉教师用书和五四学制，剩下 1911 册、52 个"学段×学科"组合。中间想直接下 PDF 提目录，下册全部 401/403，上册共 3.5GB，放弃；改成拿官方预览图做 OCR，24 册跑出 1125 行，再一册一册人工校准。

封面也卡了一次：官方图有 Referer 防盗链，第三方站直接 403。最后只给高频学科下载，压成小图 base64 内嵌，57 张，页面 762KB 自包含。

交互上一直在做减法：吸顶导航、章节 chips 锚点直达、卡片默认折叠、"今日打卡"磁贴——手机打开第一屏就能看到今天该做的 3–5 件事，不用按学科翻。

现在整站 8 个页面，纯静态，一个人维护，改完一条命令同步到云盘。

最大的体会：家长缺的不是更多内容，是"下一步做什么"。把这句话回答清楚，比收集一百个资源链接有用。

## 七、长版过程记录（公众号 / 知乎 / 存档）

### 0. 起点：一个家长的信息过载问题

孩子上小学后，我发现自己每周都在重复做同一件事：重新找一遍"这周该练什么"。

信息来源是散的——课程标准的 PDF、学校的课程表、各类书单、平台微课、竞赛通知、教材版本对照，哪一个单独看都清楚，合在一起就变成了噪声。更麻烦的是它们互相矛盾：网上流传的"名校书单"和教育部阅读指导目录不是一回事；同一本数学教材有三个出版社的版本；竞赛名单里既有白名单也有"交钱保名额"的野鸡赛。

于是有了一个很朴素的设想：把这些收进一个地方，按"年级 + 学科"组织，回答"这周该做什么、去哪儿做"。

明确不做的三件事，一开始就定下来了：

1. 不做内容托管。不传课件、不传视频、不镜像教材。
2. 不做社交。没有评论、没有排行、没有积分。
3. 不做后端。没有账号、没有数据库、没有服务器。

第三条决定了整个技术形态：纯静态页面，双击可开，扔进网盘可开，断网可开。

### 1. 骨架：8 个页面怎么切

页面的切分标准不是"内容多少"，而是"家长会带着什么问题进来"。最后落到 7 个栏目：

- **学习规划（index）**：一～六年级 × 课内 10 门 + 课外 8 模块 = 18 项，每项写目标、每日时长、任务清单。同一学段（1–2 / 3–4 / 5–6）任务一致，年级差异体现在"本学期重点"，所以 18 × 3 = 54 套任务就能覆盖六个年级。
- **能力要求（standards）**：1–12 年级的课标要求，含课时比例、识字量、古诗文篇数、高中数学学分制与学业质量五级。核心动作是把课标语言翻译成家庭动作。
- **课程推荐（courses）**：每科"1 条主线 + 少量加餐"，标注渠道与年级。刻意不堆清单，因为清单越多越不执行。
- **资料清单（resources）**：8 个分页，主体是教育部阅读指导目录小学段 110 种全表，另含英语分级、数学阅读、书法字帖、艺术、科技运动、影单。
- **赛事白名单（competitions）**：2025—2028 学年 47 项全国性竞赛全表，按类别与学段双重筛选。
- **教材目录（textbooks）**：1911 册官方电子教材的册次索引（后文详述）。
- **每周打卡（weekly-check）**：11 行 A4 横向表格，一页打印。

内容口径全部锚在四份官方文件上：《义务教育课程方案和课程标准（2022 年版）》、《普通高中课程方案和课程标准（2017 年版 2020 年修订）》、教育部《中小学生阅读指导目录（2020 年版）》、教监管厅函〔2025〕7 号（47 项竞赛名单）。凡是官方没有的（小红书上的"名校书单"、平台爆款课），只给检索关键词和甄别方法，不写进"标准"里。

### 2. 三个刻意的技术决定

**纯静态 + localStorage。** 没有后端意味着进度不能跨设备同步，换浏览器会重置。这是个真实代价，但换来的是零部署、零成本、零维护。"能用"优先于"完整"。

**只挂主域名，不挂深链。** 具体课程页的 URL 三个月就可能失效，主域名能活五年。链接失效时用户按名称在官网重搜即可。

**不做评分和排名。** 打卡只做勾选，不算完成度百分比，不给连续天数徽章。家长已经够焦虑了，工具不该再加一层压力。

### 3. 减少滚动：交互上的四层设计

页面信息量不小，所以交互的重点不是"多"，而是"少动"。

- **吸顶导航**：页签 + 章节 chips 一起吸顶，滚动时既不占屏也不失联。
- **锚点直达**：chips 由 JS 从卡片标题生成，点击平滑滚到对应卡片并自动展开，`scroll-margin-top` 预留吸顶高度。
- **卡片折叠**：首页在"全部学科"视图下 18 张卡默认折叠，只剩标题和一句话目标；单学科视图自动全展开。
- **今日打卡磁贴**：手机打开第一屏就是"今天该做的 3–5 件小事"。取任务规则是语文、数学、英语各取第 1 条为核心，三年级以上加体育，再按星期轮换一项课外。勾选与下方学科卡片双向同步（共用 localStorage 键）。

移动端单独做了一套：≤760px 视为手机，导航收进 ☰ 抽屉，卡片单列，任务行整行可点（触控目标 ≥44px），宽表横向滑动且首列吸住，110 种书单在窄屏改卡片式列表。打卡表打印态独立于屏幕态，用 Chrome print-to-pdf 校验过是 1 页。

### 4. 最难的模块：教材目录

这个栏目把"想做"变成了"能不能做"的问题，因为它撞上了版权。

- 教案是职务作品（著作权法第 18 条），学校在作品完成后两年内有优先使用权。
- 教材多为法人作品，同时因收录选文构成汇编作品，需要双重授权；中小学教科书的出版发行另有《出版管理条例》第 30 条的资质限制。
- 公网传播不属于合理使用（第 24 条第（六）项限定"少量、面向教学科研人员、不得出版发行"）。
- 2021 年底到 2022 年初，疫情期间有人把电子课本上传公网，北京互联网法院在同类案件中判了 15 起。

结论：不做内容承载。

改成索引后的形态是：只展示单元名、章节标题、起始页码、知识点条目名；每个单元挂一条官方电子教材链接；正文、插图、习题一律到官方看。

数据侧的工作量比预想大：

- 清单来自平台公开接口，4 个分片共 3565 条记录，用 `tag_list` 反推官方分类树（368 个标签），剔除教师用书、五·四学制、特殊教育、中职，得小学 835 / 初中 561 / 高中 515，合计 1911 册、52 个组合。
- 想做 24 册的完整单元明细，先试下载 PDF 抽文字层：下册 48 册全部 401/403，上册可下但共 3.5GB，放弃。
- 再试官方章节接口：7 种路径全 403。
- 最后走"官方公开预览图 + OCR"：用 macOS 自带 Vision（ocrmac）跑目录页，24 册 dump 出 1125 行文本，再逐册人工校准成 JSON。全自动解析（文字层、按坐标分栏、页码吸附）都无法收敛——目录页的跨栏标题和行尾页码一多规则就互相打架。

封面是另一次实测：官方图带 Referer 防盗链，第三方站 403；单张 1.2MB；缩放参数也 403。理论上可以 no-referrer 绕过，但那属于规避对方技术措施，也超出"只做索引"的边界，所以没有采用。最终只给高频学科下载，压成 180–220px 小图 base64 内嵌——页面自包含，扔网盘不丢图，也不产生对官方的实时请求。

### 5. 修过的 bug（按发现顺序）

1. 编号条目被误判成灰色小标题（判断条件写反）
2. 单元计数把"附录"算进去（语文只数"一"到"八"）
3. headless 旧模式最小窗宽 500px，导致 390 宽截图"右侧被裁"的假象
4. 窄屏筛选条 nowrap 造成横向溢出
5. 输入框漏写 class，样式不生效
6. 明细面板滚动被吸顶头部遮挡
7. 册次排序 `'上' == m.group(2) and 0 or 1` 短路恒返回 1，"三年级下册"排到"上册"前面
8. 高中册次是"必修 上册"而非"3上"，原封面命名规则失效，改用以 contentId 为键的封面表

### 6. 工作流：本地是唯一工作副本

站点文件平时放在本地，改完一条命令推到云盘：

```
./sync.sh status   # 看差异
./sync.sh pull     # 云端回本地
./sync.sh push     # 本地到云端，只传 html 与 README.md，同名原地覆盖
```

push 会先取云端 rel_path → file_token 再上传，避免产生重复文件；随后把 README 刷成在线文档。这样"给人看的版本"和"给自己改的版本"永远一致。

### 7. 结果

- 8 个页面的纯静态站，无后端、无数据库、无登录
- 1911 册教材册次索引，24 册完整单元明细，57 张内嵌封面，教材页单文件 762KB
- 47 项白名单赛事全表，110 种国家书单全表
- 一个人维护，改完一条命令同步

### 8. 可复用的结论

1. 家长缺的不是更多内容，而是"下一步做什么"。先回答这个问题，再谈资源。
2. 教育类站点先查授权再动手。能确定走不通的，早放弃比晚放弃便宜。
3. "索引 + 官方跳转"是绕开内容版权的最短路径，对用户价值并不低。
4. 官方资源普遍有防盗链，别假设外链能直接用；能内嵌的小图比漂亮的外链方案更可靠。
5. 筛选层数越多用户流失越快。单版本场景下，任何下拉都是负资产。
6. 纯静态不是妥协，是把维护成本压到零的一种设计选择。
